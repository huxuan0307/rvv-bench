# P1 测试与审计

新增P1套件通过显式case清单记录逐样本cycles、动态目标指令数、实际VL、数据EEW、index EEW与mask模式。传统宽表和冻结的513例历史批次保持独立。

## 构建与验收

在`instructions/rvv`目录使用`make p1`生成程序集、case header、manifest及ELF/BIN。具体参数以`p1.mk`为准；参数变化使用新的P1_DIR，保留旧产物。`make p1-run`用于NEMU功能检查。NEMU的cycle计数不能用于判断RTL吞吐。

验收包括三个独立条件：进程退出成功；没有模拟器critical error、BAD TRAP或差分错误；case manifest覆盖审计通过。不能只根据GOOD TRAP文本或退出码判通过。

```
python3 p1_extract.py --manifest build/p1/manifest.json \
  --output build/p1/results.csv --coverage build/p1/coverage.json \
  build/p1/run.err
```

manifest须声明samples，或显式传入`--samples`；两者同时存在时必须一致。程序正常输出所有样本后需打印单独的`P1_COMPLETE`。提取器要求终态标记位于样本之后，拒收缺失/重复样本、未知case、预期字段不符、实际VL或active计数不符、运行时临时skip及正确性失败。仅manifest预先声明且理由一致的skip属于可解释未覆盖，不能计作性能PASS。coverage.complete表示CSV及样本审计通过；进程状态由外层runner另外验收。

结果CSV包含measurement_valid、CPI、active_elements_per_cycle及active_bytes_per_cycle。后者按**数据EEW**计算；vle8/e64m8的数据EEW是8，index EEW同样不代表载荷宽度。算术指令的活动字节指标仅表示参与操作的数据量，不是内存带宽。QUICK计时仍含循环与读计数器开销，不自动减去经验常数。

也可用统一runner运行NEMU或RTL，分别记录stdout/stderr、退出码、timeout与覆盖审计：

```
python3 p1_run.py --build build/p1 --nemu --emu /path/to/nemu
python3 p1_run.py --build build/p1-rtl --emu /path/to/emu --reference /path/to/ref
```

runner拒绝覆盖已有运行输出。它根据实际CSV header选择guest输出流：本机NEMU的UART在run.err，RTL通常在run.log；两个流均检查模拟器错误。NEMU的`--nemu`模式只验证功能和计数，不提供微架构性能。

2026-11-03 P1基线矩阵包含47个case：ALU8、FMA8、load控制4、indexed16、mask11。后续新增4个vfmadd.vv链数case，all现为51个case；历史归档矩阵保持原样。indexed采用12/0/28/8非单调offset及独立lane数据；m8 mask额外覆盖每chunk一个活动元素和交替空chunk。ALU/mask每循环展开32条，FMA每循环96条；P1_LOOPS支持16/64/256，P1_RUNS指定样本数，P1_SUITE支持all/alu/fma/fmavv/load/indexed/mask；fma保留原.vf矩阵，fmavv专测e64m1、VL2、vfmadd.vv的1/8/16/24条独立链。warmup循环数与计时循环数相同，所有数值以manifest为准。

## 归档

在稳定构建与运行结束后创建全新的归档目录：

```
python3 p1_archive.py --build build/p1 --output ../../logs/p1-NEW-BATCH \
  --emu /path/to/emu --reference /path/to/reference \
  --command 'exact build/run command'
```

归档工具拒绝已存在的输出目录，复制程序集、manifest、ELF/BIN、当前源与日志，并记录SHA256、仓库HEAD及dirty状态。源码是归档时快照，程序集和实际测试ELF/BIN是识别执行产物的依据；不能将事后源码哈希冒充原始构建输入。模拟器和reference仅记录路径与哈希。

## 测量边界

P1核心问题是FMA独立链是否足以饱和、VL=1高LMUL的拆分成本，以及load按数据EMUL轮换后旧目的反馈的影响。indexed和稀疏mask代表矩阵需要计时外校验；未覆盖的SEW/LMUL、索引分布、mask policy、随机模式应由manifest明确说明。全零mask、每个chunk一个active元素和成组空chunk具有不同微架构意义。

普通unit/strided访存宽表现按数据EMUL选择轮换组。segment和mask-load的专用组规则未由此修复，不能把该变化称为所有访存基准依赖已消除。非对齐store不在本轮范围。
