# 真值 ULP 验收与双档候选筛选

适用于新增数学实现、改变数值路径、或声称达到某精度档的任务。**G2 的档位是候选筛选标准；G3 的预算是最终交付接口的契约。** 两者都用同一真值误差定义，但不能用前者替代后者。未改变数值路径的任务按 G0 冻结其回归范围和适用性，不能将未验证的精度写成通过。

## G0-02：冻结指标、语料和接口语义

| 指标 | 定义与用途 |
|---|---|
| `true-ulp` | 对适用有限结果，令 `t = f(x, …)` 为精确输入的数学真值、`g` 为目标格式输出所表示的精确实数。`E = abs(g − t) / S(t)`。这是 **1 / 3.5 ULP 筛选和数值预算**的指标，不将 `E` 取整。 |
| `encoding-step` | 将 `g` 与已指定来源的**目标格式参考值**（如 RNE 后的 MPFR 参考、同库标量 libm）比较有序位型距离。注明参考来源和跨零/特殊值规则；只用于兼容性、回归或冒烟。 |
| 接口语义 | 分别验证有符号零、无穷、qNaN/sNaN、定义域/极点、溢出/下溢、适用 `frm`、`fflags`、`errno`、mask/tail 和调用约定。按实际契约规定 NaN、符号和异常要求，不用 ULP 预算豁免。 |

`S(t)` 对目标格式有限范围内的正规真值为 `2^(floor(log2(abs(t))) − fraction_bits)`（f64 为 52，f32 为 23）；次正规范围、比最小次正规更小的有限真值及精确零用最小次正规间隔（f64 为 `2^-1074`、f32 为 `2^-149`）。尺度取自真值，不能用 RNE 参考或被测值的指数代替。数值距离中 `+0`、`-0` 同为实数零，但接口符号单独检查。契约域内的有限次正规结果也参加精度统计，不能仅按分类放行；有意缩小精度范围须在 G0 明示。目标溢出边界按舍入模式单独判定，不能因为有限真值大于目标最大有限值就认为返回 `Inf` 正确；输出意外 NaN/Inf 是功能问题，不得从统计中默默剔除。

例如在间距恒定的一段，真值位于某浮点数上方 `0.375` ULP、正确舍入落在该浮点数，而输出又比该浮点数低一个相同间距；编码步距为 `1`，真值误差为 `1.375 ULP`。跨二的幂时，`abs(g − r_true) / ulp(r_true)` 再取整也不等价于编码步距，更不是真值误差。

在 G0 契约与 [G3/G4 预登记矩阵](evidence-schema.md#casescsv预登记矩阵) 中绑定：

- 函数/元数、目标格式、输入域、支持舍入模式、特殊值与异常期望、ISA、ABI 入口/形状、VLEN/LMUL、有效长度和 mask（以及适用的消费者、链接/LTO 模式）、每格预算。RNE 可作获批的试点范围，不能静默删除已支持模式。明确每个公开入口原契约、候选筛选档位、最终交付预算及未覆盖项；新预算不倒填到历史数据。
- 主机 oracle 的算法、精度阶梯/资源上限、目标范围和边界规则、来源与版本（优先 MPFR），以及生成器和语料清单。G0 用契约冻结这些要求、记录已有素材的 SHA256；G1b 使用现有 `inputs_sha256` / `oracle_sha256` 冻结实际清单文件，并在清单内记录生成器、库/工具、配置、语料及参考区间数据的 SHA256。不要向 G0 CLI 添加不存在的 freeze 键。
- 固定训练/调优与独立验收语料及复算抽查策略。预登记每格输入组、分布/seed、数量、分母、独立验证样本、边界覆盖及预算；按函数、精度和风险定量，不把 4096、百万样本或特殊值个数当作统一通过条件。语料在运行前固化为精确输入位型并加哈希；随机输入不能只存 seed。把重复执行同一输入与不同输入数分开计数。
- 覆盖随机域内样本（含指数分层或对数分布）、分段/抵消/阈值邻域、极值、次正规、符号零与特殊值；二元函数还覆盖交叉输入与各分量尺度差。例如 `atan2` 的四象限、坐标轴、指数差和 `abs(x)≈abs(y)`，`log10` 的 1 邻域、次正规、0/负数和大输入，`acos` 的 `(0.5,1)` 与 ±1 内外邻域，`atan` 的极小、极大和正负输入。mask 至少区分全零/全一/混合与适用尾部，检查危险 inactive 输入但不把它当有效数值样本。

## 真值包络与逐阈值判定

1. 宿主从输入 bits 精确构造参数。对受支持的函数，MPFR 分别以 RNDD/RNDU 计算 `t ∈ [lo, hi]`；核对 oracle 的舍入契约、版本、工作精度及自身指数范围/异常。其他 oracle 只有能提供等价、经审的保守包络时才可用于验收；提高 `mpmath` 或任意普通高精度计算的精度，本身不能给出这样的证明。
2. 若区间能确定 `S(t)` 并落在适用的有限结果分类，令 `U=max(abs(g−lo),abs(g−hi))/S`；`L=0`（`g` 在区间内），否则 `L=min(abs(g−lo),abs(g−hi))/S`。用精确运算或保守外舍入比较阈值。跨零、binade 或 normal/subnormal、溢出边界时先提高精度；若已能证明统一尺度/分类或有保守的分段界也可判定，否则标未决。MPFR 自身超范围不等于目标溢出。
3. 对每个预算 `T` **独立**判定：`U ≤ T` 为该样本 `pass`，`L > T` 为 `fail`，其余随着冻结的精度阶梯细化，达到上限仍无法判定则 `unresolved`。例如 `[1.01, 1.02]` 过 3.5 不过 1，`[3.49, 3.51]` 对 3.5 未决，`[3.5, 3.5]` 对 3.5 通过。上界取最大有限样本上界，不能以平均值、显示小数、四舍五入后的最大值或不含未决的分箱来声称通过。任一必需覆盖缺失/未决不得给该档完整通过。
4. 可另做 Ziv 式**目标格式正确舍入参考**：当真值区间两端舍入到同一目标结果（含所需符号/模式）时确定 `ref_bits`，否则可细化或标未决。固定 512 位只是可能的工作精度，不是成功保证。求出正确舍入 `ref_bits` 不能代替真值区间判档；真值误差已被界定时也无需强求 `ref_bits` 可判定，除非该用例另有此要求。

**精度裁定与执行环境分开。** 真值在宿主计算；被测输出须来自对应目标实现/最终 ELF 的真实执行，逐 lane 保存位型而非打印十进制近似。精度取证优先经核验且支持目标 ISA、VLEN、舍入与 wrapper 的 QEMU-user 或 NEMU 等环境；按契约补真实目标/RTL。gsim 裸机同库标量检查或 DiffTest 单独通过不能充当真值验收。出现模型分歧时保留同输入、产物、设置和最小复现，区分环境问题与实现缺陷；未归因前不得以另一环境通过来代替失败的必测格，亦不得据此豁免 G3-05。功能环境不提供正式 G4 周期。

## G2 → G4：一套候选，两道阈值，两类决定

| 档位 | 资格（同一候选池、覆盖范围、硬门禁） | 选取 |
|---|---|---|
| Tier-1 / `u10` | 在冻结样本上能判定最大 `true-ulp` ≤ **1.0**，且硬语义/ABI 均通过。 | 该档符合冻结保护条件的最高性能实现。 |
| Tier-2 / `u35` | 在**同一**冻结样本上能判定最大 `true-ulp` ≤ **3.5**，且同一硬门禁均通过。 | 同口径排名，允许与 Tier-1 相同。 |

- G2 先过预筛的数值和硬门禁，再用同契约、同输入及同性能主指标对候选排名。基线与候选同测；候选的 SLEEF `u10`/`u35` 标签只标来源，不是合格证，不借用其次正规规则或特值/异常语义。记录 commit、许可证、编译选项和适配层。允许同一份真值/输出证据用于两个阈值，无需重复采样。G2 胜者只是在已比较范围内的预选结果。
- 对两个档各自记录 `winner`、`no_qualified_candidate` 或 `incomplete`。只有已登记候选的筛选结论齐全且无合格者才写 `no_qualified_candidate`；未决、未测、缺工具或缺可比较性能数据不能冒充完成筛选。若必交付档缺合格者，按预定规则保留合规基线或阻断，不自动改报更宽档。两档胜者相同须明示；在预定平局/噪声范围内，若 3.5 档无稳定收益，优先共用合格的 1.0 档胜者。同条件下过 1.0 就会过 3.5；若更宽档排名反而更慢，先核对噪声、条件和样本是否一致。
- G3 以最终安装库/消费者证据重新判定拟交付实现，覆盖已登记的 fixed/scalable、masked/unmasked、VLEN/LMUL、舍入与静/动态链接等适用格。约定 bit-identical 的 active 路径才要求 masked 与 unmasked 位一致；否则各自判定数学输出和状态契约。验证无 active 或 active 基准在场时 inactive 不增异常、未承诺的 inactive 返回位不比较，并验证进入/离开时 `frm` 和已有 `fflags` 的保留/累积。若交付路径覆盖消费者 LTO，则用 off/on 各自实际编译、链接、执行的输出判定 G0 登记的数值格。同一输入可共用 oracle；只有最终输出逐位相同并有实际调用/产物身份记录，才能复用误差判定。已有 `encoding-step` 成对摘要既不证明逐位相同，也不证明真值预算。
- G4 用实际安装的候选重做同口径 A/B；只有最终产物在 G3 同时满足接口预算和该档阈值，才可进入该档最终比较。最终排名可能改写 G2 排名，范围限于实际比较的候选。保护场景和最终 ABI/包装开销不可跳过；裸核和冒烟通过不能证明最终交付更快或同精度。把「G2 预选」和「已复验/未复验的最终库态结论」分开报告。
- **交付策略：** 算子库可另设显式档位，或两档共用实现；`libmvec` 默认只用两档做内部选型，公开 `_ZGV` 符号保持现有契约和 ABI，不能因 u35 更快就默认放宽。原符号若有不同预算按原契约判定，不靠档位名推断或把 `-ffast-math` 当精度选择。计划公开新精度接口时，另行设计并走[公开 ABI 集成验收](glibc-integration.md)。

## G5/G6：可复算的证据与当前工具边界

按[证据约定](evidence-schema.md#真值精度与双档证据人工审查)把语料、oracle 包络、原始逐 lane 输出、语义/状态结果、逐样本误差界及判定、各档汇总和最终选择登记为永久证据。报告分别列门槛、观测区间/上界、有限样本/独立输入/未决/失败/特殊与状态计数、最坏输入及出处、性能主/保护场景和所选路径。直方图须包含 1.0、3.5 的边界并说明未决的统计规则；直方图不能代替可定位的逐样本记录。报告写明**抽样不能证明全域上界**；如需对外作全域上界承诺，另审误差分析或可核查的全域证据。审阅者独立从原始位型/包络复算阈值附近和最坏样本、异常计数以及每档汇总，记录覆盖、版本/哈希、命令和结果；G6 检查永久清单及从数据复算路径，不依赖临时运行现场。

现有 [MPFR 分析说明](../../tests/newmath/README-mpfr-accuracy.md)及[分析器](../../tests/newmath/mpfr_accuracy.py)可作为精确输入、区间和分类的基础：当前仅支持 `sin/cos/log/logf/exp/expf/pow` 的既有采集格式，分箱含 `(2,4]`，**不能据此完整判定 3.5，也不能直接验证 `atan/atan2/acos/log10`**。正式判档前要补齐并验证工具，或提供独立审过、满足本规约的等效证据。现有 workflow CLI 检查证据身份、矩阵、数量和所报预算的形式约束，不生成真值或复算误差界，无法仅凭 `metric` 判断是否真的使用严格 oracle。当前由 G0/G2/G3/G5 独立审查阻断口径错误、缺项和未决的必需证据；`check` 返回 0 不能代替该审查。
