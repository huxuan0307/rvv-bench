# 阶段与必做检查清单

编号是稳定的审查定位符，不代表脚本已自动验证了该项。每项记录适用范围、证据入口、检查人、状态和未完成原因；条件项须注明适用性与决定人。机器检查、人工判断、独立批准分别记录，不能互相替代。

**新增函数/精度的必做分支：** [glibc API 与外层工具链集成](glibc-integration.md)是下列编号的具体接受条件，不是选读背景。G0-01 对账每个新增标量目标的 16 格（m1/m2 八格必做）；G1A-01 查 GCC 函数表和安装头握手；G1B-01 贯通真实 sysroot pilot；G2-01 在 glibc 添加实现、manifest、导出与测试；G3-01/02 验证逐格声明、选择、链接、执行与负例；G4-01 使用最终库；G5-03 对账逐格结论；G6-02 核外层 gitlink 与重建。未交付 glibc 公共 API 的裸核不得据此判通过。

## G0 契约与边界

- **G0-01** 确认需求、目标函数及精度、参数个数、ISA、固定/可伸缩、LMUL、masked/unmasked、公开/私有接口、目标平台和非目标。以当前源码和安装状态生成矩阵；区分缺失、已有、不适用和有意私有。交付或修改已安装自动向量化路径时，在 [CSV 矩阵](evidence-schema.md#consumer-ltocsv消费者-lto-配对)预登记 LTO 配对范围（含 positive、strict、适用链接模式及理由）。独立审查检查整组漏登，不能以无标记推定不适用。
- **G0-02** 规定 oracle、真值 ULP 定义和预算、抽样域与 seed、特殊值、舍入模式、flags 保存/累积、inactive/tail 语义及 ABI；同格式编码步距不能称为真值 ULP。
- **G0-03** 冻结性能指标、分母、主/保护场景、输入、接收/回退/平局规则、未覆盖处理、资源/并发/超时预算；不移植历史阈值作为通用标准。
- **G0-04** 确认 `pwd`、各仓库与子模块状态、他人未提交改动、用户授权及组件工作树；列出写入和提交负责人，保护已有现场。

**出口证据：**契约、预先登记的必测案例矩阵（planned cases）、非目标、风险和权限记录；缺失案例不能靠从结果表删行变成通过。

## G1a 设计独立批准（pilot 之前）

- **G1A-01** 阅读既有实现及候选来源/许可证；描述算法、RVV 映射、ABI/编译器影响、精度与状态风险和回滚方式。单假设尽量单独实现。
- **G1A-02** 设计真实库态和裸核口径、同源 A/B、测量完整性、正确性/RTL 矩阵和 bug 分流；明确资源预算及停止条件。
- **G1A-03** 非作者独立评审设计和测量方案；阻断问题先关闭，批准绑定契约与设计版本。

**出口证据：**设计、候选来源、测试及测量协议、独立评审和修订记录。

## pilot 与 G1b 基线/环境独立批准

- **G1B-01** 按授权执行一个端到端 pilot，验证构建、运行、收集、归档和拒收路径；不自动扩大规模。
- **G1B-02** 从明确源码和同一发布配置重建基线，记录各仓库 commit、未提交 diff、编译/链接 flags、工具链、sysroot、依赖、harness、输入、emu/refmodel/配置及 hash。构建中间树置于获准缓存，任务保留永久配方。
- **G1B-03** A/B 构建和安装前缀隔离；静态链接核验 link map/成员及 ELF hash，动态链接核验 loader 的实际映射。缓存键覆盖全部有效身份，否则不使用缓存。
- **G1B-04** 独立检查基线正确性、保护场景、实际运行身份、完整性和预算；批准后才批量运行。状态和日志只是必要条件，逐 case 还须核对完成标记、校验、身份与适用格。

**出口证据：**配方、身份清单、pilot 结果、链接证明、基线数据和独立批准。

## G2 候选预筛

- **G2-01** 工作树内实现最小候选和适配测试；先查 ISA/ABI 规范及 intrinsic 参数顺序、indexed load 字节偏移、mask/tail 策略，再运行小输入、特殊值及 mask 预检。
- **G2-02** 同一调用契约、输入和配置下筛选；区分裸核、直接 ABI、库态、自动向量化；核验实际调用和动态路径，避免 `N < VLMAX` 时全走标量尾循环却误称向量性能。
- **G2-03** 保留失败、淘汰和不确定结果；预筛结论不代替发布库态决策。疑似 bug 按模板记录、独立核规范，必要时最小复现和交叉实现；可撤回但不得抹去历史。

**出口证据：**候选清单、来源、预检、运行身份、筛选/淘汰依据和未决 bug。

## G3 最终组合正确性与 ABI 独立批准

- **G3-01** 将实现、包装器、常量、清单、导出及版本、构建条件、声明/安装头、编译器能力与测试同步；按目标矩阵检查，不硬编码历史符号总数。
- **G3-02** 验证编译器实际生成目标调用、最终链接与执行；检查旧/新编译器和头兼容、寄存器/栈、fixed/scalable、关键 VLEN 和实际 fallback 边界；实际重编重链并核验产物身份。已安装 libmvec 的自动向量化消费者交付成对 LTO off/on 结果、证据归档及本次 SDK 清单。CLI 核对矩阵、归档、结果与 coverage；审查者核对真实编译/链接选项、最终 ELF 调用和执行、静态归档成员或动态 loader 实际加载路径。中间对象引用和历史 SDK 通过不能替代。按[集成规程](glibc-integration.md)另验混合声明/LTO 链接顺序与合法回退。
- **G3-03** 按契约验证高精度 oracle、随机及边界、±0、次正规、无穷、qNaN/sNaN、定义域；标明抽样不能证明全域上界。masked 测全零/全一/混合及尾部，inactive 放危险输入，验证 active 结果和 inactive 不额外置异常。
- **G3-04** 验证支持的舍入、`frm` 恢复及已有 `fflags` 保留/累积；不能在 active 本就触发异常时要求全局 flags 一律为零。known-fail、skip、未测与新失败分列。
- **G3-05** GCC 或高风险 ISA/状态改动验证对应 RTL 真实路径；仅 QEMU/NEMU 通过不够。独立代码/正确性审查绑定最终组合，阻断项修复并复测后复审。

**出口证据：**实际矩阵与状态、源码/二进制身份、ABI/数值/状态及 RTL 记录、审查结论与未覆盖项。关键必需格未通过不得进入最终采纳。

## G4 最终库态性能独立批准

- **G4-01** 最终组合重新构建及链接 A/B；按预注册主/保护场景测试受影响入口、长度、批次、mask、冷/热路径。每个变体先功能预检、后同口径 A/B，保留负结果。若声称消费者 LTO 改善性能，另设 off/on A/B：只切换消费者 LTO，锁定源码、原生库、工具、输入与目标环境，保存动态调用和周期窗口。内联备注、静态调用点计数和 QEMU 功能结果均不是提速证据。
- **G4-02** 记录真实调用、N、K、实际循环及计时窗口、预热、原始周期、归一化公式和单位；窗口的实际调用数/元素数已含 `timing_repeat` 时只除一次，禁止重复除算。允许按已声明的 uint32/uint64 宽度处理计数器回绕，但必须校验有效范围与窗口。
- **G4-03** 性能比较使用同一模拟器及版本、输入和配置；不得比较 gsim 与 verilator 的程序性能高低。相同二进制重复窗口不是独立统计样本；多输入衡量敏感性，未预定权重不得事后挑选。
- **G4-04** 只接受完整、状态正确、检查和及身份可核验的 case；同一 run、同一 case 的固定输入重复测量不得发生 checksum 漂移，但 A/B 的 checksum 可以不同，不能仅凭不同就拒收。取消、失败、部分窗口与零样本不得混入汇总。阈值以未舍入数据判断，接近阈值时按预定策略扩充验证或标为不确定。
- **G4-05** 如涉及延迟/波形：证明机器级 RAW 反馈闭环与计时边界；检查真实动态配对、ROB 代际、提交与窗口完整性，拒收有歧义的调用/窗口并说明样本量。EX0 间隔不等于功能单元固有延迟；静态追踪不是通用数据流证明。

**出口证据：**A/B 绑定身份、原始测量和筛除记录、汇总、回退决定、独立数据/口径审查。未测入口不得声称无回退。

## G5 数据和报告独立批准

- **G5-01** 长期证据先归档并校验：接受的原始数据与汇总分开入 `data/`；定位所需失败输入、日志和波形入 `bug/`；获准可复用脚本入 `script/`。工具原始证据不改写，旧路径在说明中解释。
- **G5-02** 报告及持久说明不得依赖 `tmp/`、`log/`、运行目录或构建中间树；以源码提交、永久配方与数据为主要依据。报告文件标状态/阶段，解释列名、类别、单位、统计口径、身份、限制与失败。
- **G5-03** 独立逐值核对权威 CSV、表格、图轴、摘要、链接、数据和结论；相对路径、有效版本与取代关系一致。自动映射只能检查结构化数值，定性结论与因果须人工评议。
- **G5-04** 已取代报告标明替代关系，维护索引；历史对象不存在应明确不可现场复验，不补造命令或身份。布局检查包含顶层文件与目录白名单及已获准例外。

**出口证据：**永久数据索引、有效报告及 SVG、引用和布局检查、独立数据/合规批准。

## G6 交付与授权收尾

- **G6-01** 唯一集成人等待必要人员完成，审查最终 diff、实际测试和 `git diff --check`；检查所属仓库、暂存范围和其他会话状态。
- **G6-02** 经授权或已明确包含的代码交付，按仓库提交实现、测试及文档；外层子模块指针由授权集成人处理，任务记录、构建产物和一次性脚本不入库。push/发布另需授权。
- **G6-03** 回报提交/分支、矩阵和限制、证据入口、未完成项及清理状态；询问用户是否清理。删除前核实解析后的绝对路径、大小、依赖、Git 状态、作业/会话占用与授权；迁移先校验再删除。

**出口证据：**交付清单、各仓库身份、批准及明确未完成项；未获授权的操作保持未执行。
