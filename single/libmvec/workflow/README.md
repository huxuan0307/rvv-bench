# RISC-V libmvec 自主迭代流程

本目录定义需求、实现、验证、审阅和交付的统一流程；首版门禁工具只支持须完整经历正确性、ABI、库态性能和报告的 **full-development profile**，不提供仅正确性、仅报告或 G4 不适用的完整流程。它不是调度器，也不授权自动启动仿真、提交、推送或删除。正式代码修改只能在任务目录 `worktree/` 对应仓库内进行；任务记录和数据不应成为源码运行依赖。

## 状态机

`G0 契约 → G1a 设计批准 → pilot → G1b 环境/基线批准 → G2 候选预筛 → G3 最终正确性与 ABI → G4 最终性能 → G5 数据和报告 → G6 交付`

状态表示门禁的完成，而不是 agent 数量或进程退出。G1a 独立批准先于 pilot；G1b 独立批准先于批量实验。任一必需证据缺失、失败、未运行、身份不明或签核失效时停止推进；不适用须说明依据。候选预筛通过只允许进入集成，不等于最终采纳；正确性或 ABI 失败不能由性能抵消。高风险 GCC/ISA/状态修改缺少要求的 RTL 验证时保持未完成，不得无条件豁免。

每个门禁冻结其输入、适用矩阵、配置、结果、评审及上游状态身份。代码、未提交差异、工具、配置、构建、输入、数据、报告或评审对象变化时，按依赖关系使受影响门禁和后续结论失效，重新检查及独立审批。单项优化须分别作可回滚决策；最终组合须重新完成正确性、ABI 与发布库态性能回归。

## 证据与审查原则

- 所有结论区分已观察事实、设计假说和未验证事项；当前源码不能因历史报告或旧构建通过而自动通过。
- 一份适用矩阵明确每格 `pass`、`fail`、`skip`、`not_run` 或 `not_applicable` 及原因；`skip` 和 `not_run` 不是通过。
- 独立审查者不能是所审代码或证据的作者；Lead 核对 DSH 会话及事件与实际审查内容。工具只做机器可验证的格式、身份和状态检查，不能保证审查者真实独立、签名真实性、语义正确或运行时权限隔离。
- 用户可读报告与汇总用 Markdown、CSV；图用 SVG。报告以源码提交及已归档的 `data/` 记录为主要证据；确需引用 `build/` 产物时只能引用已登记来源与 SHA 的产物，并同时提供代码提交和永久配方，不能让可删除产物成为唯一证据。
- 程序和数据输入显式指定，不从旧任务号或缓存猜测；异常、失败、取消与未完成数据不可混入正式汇总。涉及特殊值、舍入或 masked 语义的变更必须先冻结契约再判断结果。

## 授权优先

更高优先级的系统、用户指令及适用范围更具体的仓库规则优先。启动新任务、持久运行输出、脚本、提交和清理均遵守当次授权；推送、发布和删除需单独授权。用户禁止的运行不得借由状态推进或脚本间接执行。已停止测试不得自动恢复；重新运行须依据最新用户授权。[工具与恢复](docs/operation.md)给出检查边界。
